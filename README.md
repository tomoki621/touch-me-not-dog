# 触らせてくれない

床や机に立たせて、追い払わせて撮るためのもの。

https://tomoki621.github.io/touch-me-not-dog/

## 3つのページ

**3つとも同じ AR の作り**になった。WebXR の `immersive-ar` でヒットテストを使い、
床や机の面を検出してそこへ置く。置いたあとカメラが動いてもキャラは動かないので、
歩いて回り込める。URL はページごとに別。

| ページ | 何が出るか | 操作 |
|---|---|---|
| `index.html` | ルイーズ | 置く／盾・威嚇・剣 |
| `elf.html` | エルフの剣士 | 置く／守備・斬る |
| `exodia.html` | 封印されしエクゾディア | 置く／召喚・エグゾード・フレイム |

**WebXR が無い端末では貼り付け表示に落ちる。** `immersive-ar` は Android の Chrome
などにしか無く、iPhone の Safari には無い。そちらではカメラ映像の上に 3D を重ね、
位置も指で決める。撮れることは撮れるが、「その場に居る」感じは出ない。

**カードは使わなくなった。** 以前はルイーズとエルフだけ MindAR でカードを
マーカーにしていた。カードは位置・向き・実寸を全部教えてくれるうえ、影が実物の
カードに落ちるので接地が完全に成立していた。**そこは確実に落ちている。**
引き換えに、カードを持ち歩かなくてよくなり、カードを画面に入れ続ける必要も、
外した瞬間に見失うこともなくなった。

`targets.mind` と `elf.mind`、そして `compile.html` は消していない。カード方式へ
戻したくなったときのため。今はどのページからも読まれない。

**手の検出も外した。** 手をキャラの後ろに回す遮蔽と、手を近づけると斬る仕掛けが
あったが、WebXR のパススルー映像はページから触れず、MediaPipe に渡すフレームが
無い。貼り付け表示でだけ動かす手もあったが、要らないので消した。

## 準備

```sh
npm install
node tools/build.mjs                 # 束ねて版番号を書く
python serve.py 8443                 # スマホの実機で見る（HTTPS）
```

カメラは HTTPS か localhost でしか許可されない。`serve.py` は自己署名の証明書で
HTTPS を立て、3ページぶんの URL を出す。スマホ側で一度だけ警告を承知して進む。

動くかどうかは、押して確かめる。

```sh
node tools/sim.mjs app      # ルイーズ
node tools/sim.mjs elf      # エルフの剣士
node tools/sim.mjs exodia   # エクゾディア
```

## ルイーズ

輪を床や机に合わせて「置く」→ その場に立つ → 右の3ボタン（盾・威嚇・剣）。
盾は押しっぱなしで構え続ける。キーの `1` `2` `3` でも出せる。
2本指、またはボタンで大きさと向き。

**リギングはしていない**……はずが、あとからリグありのモデルに差し替えた。
腕は骨で振る。剣と盾は手の骨の子なので、腕の動きに完全に追従する。

**Meshy はどの書き出しも同じ箱に正規化する。** 3体とも高さ 1.9 で出てくるので、
剣と盾の相対的な大きさと握り位置はコード側で組み直している（`fit()` と `SWORD_LEN`）。

**カードをやめて消えたもの。** カードの面内の回転を 90 度単位に丸めて打ち消す
仕掛けと、見失ったときに最後の姿勢で残す仕掛け。置き場所が動かなくなったので、
どちらも要らない。追跡が崩れた行列を捨てる判定も同じ理由で消えた。

## エルフの剣士

`elf.html`。置く仕組みはルイーズと共有（`src/arstage.js`）。違いは装備と動作だけ。

**右手に剣、左手は空。盾を持たない。** ボタンは2つ（守備・斬る）。キーは `1` `2`。
威嚇は無い。

**守備は「ひざをついて剣を横に構える」。** 盾が無いぶん、受けは剣の腹でやる。
右のひざを地に、左のひざを立て、刀身を体の前へ真横に渡し、左手を刃に添える。
押しているあいだずっと構え、離すと立ち上がる。

**ひざをつくと腰は自分では下がらない。** 骨を回すだけでは足が動くだけで腰は
その場に残り、宙に浮いたまま脚を折った形になる。体ごと沈める必要がある。

その量は守備の重みに対して**直線でも単調でもない**。重み 0.1〜0.3 のあたりでは、
前へ振り出した左足が先に床を割る（腰はまだ落ちていないのに脚だけ伸びるため）。
式で近似すると、そこで 0.09 めり込む。なので実測をそのまま表にして引いている
（`src/elfpose.js` の `KNEEL_LOW`、0.125 刻み）。値は `node tools/elfpose.mjs table`
が出す「沈める前の、skin を通した体の最下点」。今は 0〜1 のどこでも床に乗る。

**姿勢は `src/elfpose.js` の表にだけ置いてある。** 表だけでなく、それを骨に当てる
`applyPose` も同じファイルにある。アプリ（`src/elf.js`）と描き出しの道具
（`tools/elfpose.mjs`）が**同じ関数を呼ぶ**ので、「表は同じなのに当て方がずれていた」が
起こらない。ここで見た姿がそのまま画面に出る。

```sh
node tools/elfpose.mjs guard.png 1 0 0   # ひざをついた守備
node tools/elfpose.mjs swing.png 0 0 1   # 薙ぎの打点
node tools/elfpose.mjs rest.png  0 0 0   # 素の姿勢
```

床は `y=0` の線で引いてある。**ひざが浮いているか埋まっているかは、この線との差で
しか分からない。** 数字でも最下点を出す。

**胴の X まわりは、正が前へ屈み、負が反る。** ルイーズのコードには「守備は前へ
屈み（負）」という注釈が残っているが、実際に描き出すと負は反りだった。符号を
そのまま写して、エルフが天を仰いだまま構える形になった。**注釈ではなく絵で確かめる。**

**剣は背丈の 55% に落とした。** Meshy の剣は箱に正規化されて出てくるので、
そのまま持たせると槍のように長い。横に構えたとき体の幅に収まらず、守備に見えない。

**握りは数字で決め打ちしない。** 手の骨は拳ではなく手首にある。そのまま剣を置くと
手首に刺さって見える。前腕から手までの長さを実行時に測り、その 0.62 倍だけ骨の
向きへ送って拳の中に柄を置く。模型を差し替えても柄の位置がずれない。

**骨の名前はルイーズと同じだった。** Meshy の二足歩行リグは `Hips` `Spine02`
`RightArm` `RightForeArm` `RightHand` … の規則で揃っている。だから姿勢の書き方
（`boneSet` と `aimBone`）がそのまま乗った。腕は角度ではなく「どちらへ向けるか」で
書いてあるので、腕の長さの比が違っても崩れない。

**剣は 207万三角形あった。** 中身はほぼテクスチャではなく、メッシュそのもの。
`weld` してから `simplify` で 1.8万まで落とすと、見た目は変わらないまま 78MB が
0.8MB になる。減量は `node tools/slim.mjs <元> <先> 1024 18000`。
本体（リギング済）は 8192 の PNG が効いていて、1024 の JPEG に落とすだけで
17.5MB → 1.2MB。

## エクゾディア

`exodia.html`。5枚のカードを並べ、その真ん中に十字を合わせて「召喚」を押す。
立ったら「怒りの業火 エグゾード・フレイム」で技を放つ（キーは `f`）。

**マーカーを使っていない。** カードは実写に写っているだけで、位置は指で合わせる。
足元は画面のちょうど真ん中に置いてあり、十字を合わせたところに立つ。
5枚を学習させて重心を採る手もあったが、ホロ加工は反射で見え方が変わるうえ、
5枚に散ると1枚あたりが小さく写るので、認識に賭けるより手で置いたほうが速くて確実だった。
1本指で位置、2本指で大きさ・向き・傾き。カードのスキャンも `.mind` も要らない。
**傾きが要るのは、机を斜めから見ているから。** まっすぐ立たせると原理的に必ず浮く。

**モーションは一つも使っていない。** Meshy が付けてきた3つ（Idle・呪文詠唱・格闘）は、
どれも前かがみに屈んだ怪物の姿勢で、格闘に至っては最後は床に倒れ込む。
エクゾディアの立ち姿は**素の姿勢そのもの**で、腕を広げて正面を向いている。動かさないのが正しい。
だから mixer を持たない。止まって見えないよう、呼吸と微かな揺れだけコードで足している。
素の姿勢は既にカメラの側（+Z）を向いているので、向きの補正も要らない。

**見ないまま数字をいじらない。** 向きも立ち姿も、推測で回転を足して二度外した。
`tools/expose.mjs` はスキニングとモーションを自前で計算して PNG に描き出す道具で、
これで「カメラから見た図」を確かめてから直した。`tools/render.mjs` は素の姿勢しか描けない。

**技は「怒りの業火 魔神火炎砲（エグゾード・フレイム）」。** 両手を胸の前で寄せて球を左右から抱え、
光の球が育ちきったところで右手を突き出して撃つ。左手は右手に添える。頭から終いまで 4.6 秒、
うち溜めが 2.5 秒。**溜めは「大きくなっていく」で見せる。** 放つ直前に縮めると、そこで一度
終わって見える。原作の絵も、広げた両手のあいだで球が膨らんでいく形になっている。
姿勢と時間割は `src/flame.js` の表にだけ置いてある。**腕は角度ではなく「どちらへ向けるか」で書く**
（`aimBone`）。骨ごとのローカル軸の取り方に振り回されず、素の向きは読み込み時に模型から
測るので、模型を差し替えても腕だけ捻れることがない。体幹は息づかいと同じ骨を取り合うため、
`boneSet` の中で足し合わせて一度だけ渡している。息と技で2回呼ぶと、後から呼んだほうしか残らない。
体をひねった分は首と頭で同じだけ引いてあるので、狙いは正面を向いたまま。
**右肩を前へ送りすぎない。** あの大きな肩の当てが正面から顔を隠す。送るのはひねりの分だけ。

**手の向きは掌と指の両方で決める。** 腕を向けただけでは、手がどちらを向くかは最短回転の
成り行きで決まり、前へ伸ばした腕の掌はたいてい上を向く。掌だけ合わせても、今度は軸まわりが
決まらず指が横を向く。だから掌の法線と指の向きを模型から測っておき（`node tools/palm.mjs` →
`FLAME_PALM` / `FLAME_FINGER`）、その2本から姿勢を組んで渡す。手の骨のローカル軸が
どう取られているかは当てにしない。放つときは掌が正面・指が上（掌底で押し出す形）、添える
左手は掌を右腕へ・指を腕に沿わせて前へ、溜めのあいだは球を左右から挟むので掌は内側。
手首は曲がるが、腕を前へ伸ばしたまま掌を前へ向けるには曲げるしかない。

**光は手首から出さない。** この模型の手は前腕ほどの長さがある。骨の位置からそのまま出すと
掌ではなく手首の手前から光が出るので、指の向きへ前腕の 0.35 倍だけ送った「掌の真ん中」から
出している。玉もそこの中点に置くので、両の掌にちょうど触れる。

**腕を止めない。ただし震わせない。** 腕をこちらで作っているあいだ、息づかいは効かなくなる。
2秒以上ぴたりと止まった腕は人形に戻るので動かすが、細かく震わせると力んで見えるどころか
ただ手ぶれた絵になる。溜めは息と同じ遅さ（1秒に1回ほど）でゆっくり。速い揺れは撃っている
あいだだけ。

`node tools/expose.mjs models/exodia.glb pose.png flame` で技の姿勢を4枚描き出せる。
アプリと同じ表を同じ順番で当てているので、ここで見た姿がそのまま画面に出る。
掌が胸のどこに来ているかは数でも出る（胴の前面は高さ 1.05〜1.25 で z=0.39）。

**光は骨から生やす。** 玉は両の掌の中点、光線は右の掌。座標で置くと、姿勢を直すたびに
置き直しになる。光線の濃淡（手元が濃く遠くで消える）は絵を流さない。流すと根元が
暗くなる瞬間ができるので、衣のほうを芯のまわりに回して走らせている。

**出現はディゾルブでやる。** パッと出さない。予兆（魔法陣）・霧・光の柱・像を結ぶ・
解放（衝撃波）の5段をおよそ6秒、重ねながら進める。本体はマテリアルにシェーダを差し込み、
世界座標の高さ＋ノイズでしきい値を切って、足元から順に実体にする。境目は金色に光らせる。
霧は板をカメラに向け続けているだけ。加算合成なので実写の暗いところでも白く光る。
魔法陣も霧も canvas で描いているので、画像ファイルは1つも増えていない。

**隠すのに `visible` を使っていない。** しきい値を下限に置けば全部が捨てられて見えなくなる。
こうしておくと最初の1フレームでシェーダが焼かれるので、召喚の瞬間に固まらない。

**元データは 83MB あるが、重いのはメッシュではない。** Meshy の出力は
19,091 三角形しかなく、中身はほぼ 8192x8192 の PNG 1枚（77.7MB）だった。
テクスチャを 2048 の JPEG に落とすだけで 2.3MB になる。減量は `tools/exslim.mjs`。

**16個すべてが同じメッシュ・同じ骨のモーション違いだった。** 使うのは立ち姿の1つだけなので、
本体 `models/exodia.glb` 以外は要らない。

## 全体に効いている話

**置く仕組みは `src/arstage.js` に一本化した。** ルイーズとエルフの剣士が同じものを
読む。WebXR の起動、貼り付け表示への退避、ヒットテスト、輪、指の操作（大きさ・
向き・傾き）、置く／置き直す、までが入っている。
**エクゾディアは自前の同じ仕組みを抱えたまま**にしてある。あちらは効果と絡んで
組んであり、動いているものを触る利が無い。**置き方はエクゾディアが正**で、
`arstage.js` はそれに合わせる。

**輪は当たった面の上にしか出さない。置いた座標は書いたきり。** どちらも一度は
反対のことをやった。面が見つからないときはカメラの前に輪を出して指で決めさせ、
置いたあとは錨（`XRAnchor`）で毎フレーム現実へ結び直していた。前者は輪が
こちらについて回る形になり、後者はエクゾディアと挙動が割れた。両方外して
エクゾディアに揃えてある。代わりに、**面の出ない部屋では置けない**のと、
**端末が自己位置を測り直すと少し流れる**のは受け入れる。

**AR は実寸。** 背丈 1.9 のまま置くと 1.9m の巨人になる。机の上の置物として
既定を 25cm（`AR_H`）にし、あとは指で決めてもらう。指の幅は 6cm 〜 1m ほど。

**置く前に技を出させない。** 面を選べていないうちに押せると、宙で構えることになる。
動作のボタンは置いてから出す。ただしボタンを隠すだけでは鍵や連打で届くので、
`tools/sim.mjs` は「置く前に押す」も通している。

**接地は影で作る。** カードが無いので影の落ちる相手がいない。`ShadowMaterial` の板を
足元に敷くと、影の落ちたところしか描かれないので、現実の机の上に影だけが乗る。
それとは別に、接地点へ濃い落ち影を敷いてある。これが無いと、位置が合っていても浮いて見える。

**動くかどうかは動かして確かめる。** 掌の位置を出す関数が、消し忘れた変数を掴んだまま
残っていて、技を押した最初の1フレームで例外を投げ、そこで画面が止まった。束ねる側は文句を
言わない（ただの名前として通る）。`tools/sim.mjs` は DOM と WebGLRenderer を偽物に差し替えて
アプリを丸ごと走らせる道具で、押す・待つ・押すを順にやって例外が出ないかだけを
見る（絵は塗らない）。three は本物のままなので、骨も行列も姿勢も実物が走る。
WebXR は無いので3ページとも貼り付け表示の側を通る。ルイーズとエルフでは
「置く前に斬る」「守備で押しっぱなしにしたまま斬る」「置き直してもう一度」まで通す。
同じ骨を取り合う道はここで出る。

**色が黒く濁ったら、まず three の版を疑う。** ここは 0.149。`renderer.outputColorSpace` と
`texture.colorSpace` が入るのは 0.152 からで、この版に書いても新しい属性が生えるだけで
誰も読まない。出力が線形のまま画面へ行き、中間調が軒並み沈む。`outputEncoding` と
`texture.encoding` が正しい。`THREE.SRGBColorSpace` という定数は 0.149 にもあるので気づけない。

**HTML には中身を置かない。** GitHub Pages に10分キャッシュされるので、修正が届かない。
CSS も JS もモデルも外部ファイルにして、`build.json` の版番号を毎回取りに行って付ける。
`build.json` 自体も `?t=` を付けて取る。no-store を無視する端末があるため。

**リポジトリに入れていないもの。** `素材/` の中身（原寸の GLB、カードのスキャン）。
ただし `素材/下絵/キャラ/`（構想の絵）だけは入れてある。
