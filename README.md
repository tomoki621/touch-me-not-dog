# 触らせてくれない

カメラに映した机や床に紫のネズミ戦士を立たせて、盾・威嚇・剣で追い払わせる。撮って遊ぶためのもの。

https://tomoki621.github.io/touch-me-not-dog/

| ファイル | 中身 |
|---|---|
| `index.html` | 本命。カメラ背景 + 3ボタン操作（盾・咆哮・剣） |
| `hand.html`  | 手検出版。MediaPipe HandLandmarker で指先を追い、近づくと自動で反応する |
| `tap.html`   | カメラなしのタップ版 |
| `build.sh`   | `tap.html` を Artifact 用の断片に変換 |

## 操作

1. 画面タップでカメラ起動（ブラウザがユーザー操作を要求するので省略できない）
2. ドラッグで立ち位置、2本指ピンチで大きさ → 「ここに立たせる」
3. 右の3ボタン。盾は押しっぱなしで構え続ける。キーの `1` `2` `3` でも出せる

決定後はドラッグしないと犬は動かない（撮影中の不用意なタップで飛ばないように）。

## 動かす

カメラは **HTTPS か localhost でしか許可されない**。`file://` や `http://192.168.x.x` では起動しない。

```sh
python -m http.server 8000 --bind 127.0.0.1
```

## 実装メモ

**なぜ手検出をやめたか。** 参照動画の右側にあるのは盾・咆哮・剣の3ボタンで、
つまり本家も検知ではなく手動操作。撮る道具として見るなら、押した瞬間に必ず出るほうが
強い。8MBのモデル読み込み、誤検知、明暗への依存という不安定要因がまとめて消える。
検知版は `hand.html` に残してある。

**リギングをしていない。** 腕は肩から手先へ円柱を1本引き伸ばしているだけ（`stretchLimb()`）。
犬もすべてプリミティブ（球・円柱・円錐）で、外部アセットは0。

**平面検知はしていないが、水平は合わせている。** WebXR Hit Test は iOS Safari 非対応で、
さらに immersive-ar セッション中はカメラ映像のピクセルを取れない。代わりに
DeviceOrientationEvent で端末の傾きを読み、仮想カメラを実機と同じ姿勢にしている。
これで仮想の地面が現実の水平面と平行になり、床に載って見えるようになる（3DoF）。

**パースも実写に合わせる。** 実写と 3D の画角がズレていると、姿勢を合わせても合成に見えない。
背面カメラの水平画角を 65° と仮定し、映像解像度と object-fit:cover の切り取りから
垂直 FOV を逆算して `camera.fov` に入れている（`updateFov()`）。

**接地は落ち影が主役。** 方向光の影だけでは弱いので、足元に放射グラデーションの
落ち影を常時敷いている。これが無いと姿勢を合わせても浮いて見える。

**残る制約は平行移動。** 取れるのは回転だけなので、端末を持って歩くとズレる。
そこまでやるなら ARKit / ARCore、つまり Unity + AR Foundation の領域。

**キャラは設定画から手で起こしたプリミティブ。** `キャラ/` にあるのは三面図の PNG で
3D モデルではない。トゥーンシェーダ＋裏面を膨らませた黒フチで絵柄に寄せている。
本物の .glb が用意できたら GLTFLoader に差し替えるだけで乗る。
